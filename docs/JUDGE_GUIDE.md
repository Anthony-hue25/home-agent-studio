# Adaptive Stay judge guide

Open the [live application](https://ad-eaa7c5234e71450e9b279c154dc91a52.ecs.us-east-1.on.aws). No installation is needed. The browser simulates an Alexa+-style surface; physical device execution is simulated.

1. Open **Experience Lab**.
2. Select **C — Multiple simultaneous shared constraints**.
3. Inspect the climate and hot-water conflicts, then select **Formulate & Dream stay**.
4. Inspect **Verified Stay Blueprint**, **Dream evidence: PASS**, and **Current**. Strands and Bedrock propose a way forward; Dream independently verifies the configuration.
5. Select **Activate stay**. Look for **Verified Active.**
6. Open **Why can I trust this?** for model-call evidence, deterministic verification, and independent simulated gateway readback.

The controls are quick to navigate; model inference time varies.

For stale-plan protection, return to **Experience Lab** and select **D — Reality changed**. This loads a verified Blueprint followed by a preference change. **Stale — Dream again** appears and **Activate stay** is disabled. Select **Dream again**, inspect the new current Blueprint, then activate it. The server also rejects stale activation directly; see the HTTP verification checks.

For a simpler climate conflict, select **B — One shared climate conflict**. For fail-closed behavior, select **E — Truly infeasible**, then **Formulate & Dream stay**. No verified strategy means no Blueprint is issued.

The UI presents the verified outcome and evidence without a menu of alternative candidates. The simulated gateway applies and independently reads back state before activation is reported successful.
